# Security Policy

## Reporting a vulnerability

Use GitHub Private Vulnerability Reporting for this repository when available. Otherwise, contact the repository owner through GitHub before sharing sensitive details.

Please do not open a public issue containing credentials, provider coordinates, private infrastructure identifiers, personal data, access tokens, or real evidence.

## Scope

Reports are especially useful for cross-site scripting or unsafe browser rendering, request-boundary or CORS bypasses, authority-boundary violations, unsafe path handling, secret exposure, container privilege escalation, and dependency or build-chain compromise.

Good-faith security research should avoid service disruption, destructive actions, privacy violations, and access to data beyond what is necessary to demonstrate an issue.
